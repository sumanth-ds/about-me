Key Features

Enterprise-grade capabilities for production deployment

Hybrid Search

Combines vector similarity (FAISS), BM25 keyword search, and Tavily web search for comprehensive retrieval across all data sources.

Smart Query Routing

Intent-aware routing analyzes query context and automatically directs to the optimal retrieval source — vector DB, web search, or cached results.

Multi-Level Caching

L1 Redis cache for exact matches, L2 FAISS semantic cache for similar queries. Reduces latency and API costs by 60%+.

Educational AI

Multi-level explanations (beginner to expert), personalized learning plans, concept dependency mapping, and adaptive difficulty.

Web Scraping

Playwright-based scraping with anti-bot stealth, automatic retry, content extraction, and rate limiting for reliable data collection.

FastAPI Backend

Async, high-performance Python API with automatic OpenAPI docs, dependency injection, background tasks, and WebSocket support.

Quick Start

Get the system running in minutes

Install Dependencies

Clone the repository and install all dependencies including dev tools:

pip install -e ".[dev]"
Copied!

Configure Environment

Copy the example env file and fill in your API keys:

cp .env.example .env
Copied!

Key variables to set:

  • DATABASE_URL — PostgreSQL connection string
  • REDIS_HOST — Redis host for L1 cache
  • GROQ_API_KEY — Groq LLM API key
  • TAVILY_API_KEY — Tavily search API key

Run Database Migrations

Apply the latest Alembic migrations to set up your PostgreSQL schema:

alembic upgrade head
Copied!

Start the Server

Launch the FastAPI server with hot-reload enabled:

uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
Copied!

API docs available at:

  • Swagger UI: http://localhost:8000/docs
  • ReDoc: http://localhost:8000/redoc

FAQ

Common questions about the Scalable Retrieval System

How does the hybrid search combine different retrieval methods?

The orchestrator runs FAISS vector similarity search, BM25 keyword search, and optionally Tavily web search in parallel. Results are scored, deduplicated, and ranked using a reciprocal rank fusion algorithm before being returned to the user.

What is the difference between L1 and L2 caching?

L1 (Redis): Stores exact query-to-response mappings. Fastest lookup (~1ms). Used for repeated identical queries.

L2 (FAISS semantic): Stores embedding vectors of past queries. Finds semantically similar queries using cosine similarity. Catches paraphrased questions that L1 would miss.

How does the smart query routing work?

The router uses a lightweight LLM call to classify query intent (factual, exploratory, educational, etc.) and maps it to the optimal retrieval source. For example, factual queries go to the vector DB, current events go to web search, and learning requests go to the educational AI engine.

Can I use this without Redis or PostgreSQL?

The system is designed to degrade gracefully. Without Redis, L1 caching is skipped. Without PostgreSQL, document metadata is stored in-memory. The core FAISS search and web scraping features work independently. However, for production use, all components are recommended.
