VoIP Platform
Full-Stack Multi-Tenant Communication

A production-grade multi-tenant VoIP communication platform with mobile SIP client, web admin dashboard, FreeSWITCH integration, and AI-powered speech services.

Key Features

Enterprise-grade VoIP capabilities across all layers

Mobile SIP Client

Cross-platform Expo React Native app with SIP-over-WebSocket, WebRTC, contacts, chat, DTMF, and 4 UI themes.

Web Admin Dashboard

Vite + React 19 admin panel with stats, tenant management, user CRUD, SIP credentials, and filterable call logs.

FreeSWITCH Integration

Docker-based FreeSWITCH with mod_sofia, mod_websocket, mod_esl, XML curl for dynamic user directory and dialplan.

Multi-Tenant Architecture

Every model has tenant_id FK, JWT with tenant claims, role-based access (tenant → admin → super-admin).

AI Speech Services

Offline STT with Vosk, TTS via edge-tts (primary) and gTTS (fallback), call transcription pipeline.

JWT Authentication

Secure JWT auth with tenant extraction middleware, admin/super-admin decorators, and role-based route protection.

Multi-Tenant Architecture

Isolated tenant data with role-based access control

Data Isolation

  • Every database model has tenant_id FK
  • FreeSWITCH multi-tenant="true"
  • Domain-based user directory

Authentication

  • JWT with tenant_id, role, is_super_admin
  • Middleware extracts tenant context
  • X-Tenant-ID header fallback

Role Hierarchy

  • @tenant_required → tenant users
  • @admin_required → tenant admins
  • @super_admin_required → platform ops

FreeSWITCH

  • Dynamic user directory via XML curl
  • Dynamic dialplan from Flask
  • CDR callback to backend

Quick Start

Get all components running locally

Backend Setup

Set up the Flask backend with PostgreSQL:

cd backend
python -m venv venv
venv\Scripts\activate    # Windows
pip install -r requirements.txt
# Configure .env (see .env.example)
flask db upgrade
python run.py
Copied!

Mobile App Setup

Install Expo dependencies and start Metro bundler:

npm install
npx expo start

# Run on device (WebRTC requires native build)
npx expo run:android    # or npx expo run:ios
Copied!

Dashboard Setup

Start the Vite dev server:

cd dashboard
npm install
npm run dev
# Opens at http://localhost:5173
Copied!

Full Stack with Docker

Run everything with Docker Compose:

docker compose up --build
# Backend:    http://localhost:5000
# Dashboard:  http://localhost:5173
# FreeSWITCH: SIP 5060, WS 8082, WSS 7443
Copied!

FAQ

Common questions about the VoIP Platform

How does the SIP-over-WebSocket work?

The mobile app uses raw SIP-over-WebSocket (no external SIP library) to communicate with FreeSWITCH. CallContext.tsx implements SIP REGISTER with Digest MD5 auth, SIP INVITE with SDP offer (WebRTC), ACK/BYE/INFO (DTMF), and incoming call handling. The media path goes through react-native-webrtc → RTCPeerConnection → SDP exchange via SIP body → RTP to/from FreeSWITCH.

Does the STT/TTS work offline?

STT (Vosk): Fully offline. Uses vosk-model-small-en-us-0.15 which auto-downloads on first request to ~/.cache/vosk/. No API key needed.

TTS: Online. Primary: edge-tts (Microsoft Edge, excellent quality). Fallback: gTTS (Google). Both require internet but no API keys.

How does multi-tenancy isolation work?

Every database model has a tenant_id foreign key. JWT tokens include tenant_id, role, and is_super_admin claims. Middleware extracts tenant context from JWT (or X-Tenant-ID header). Role-based access decorators (@tenant_required → @admin_required → @super_admin_required) enforce isolation at the API layer. FreeSWITCH uses multi-tenant="true" with domain-based user directory.

Can I run this without Docker?

Yes. The backend and dashboard can run without Docker. FreeSWITCH can be installed natively (requires more configuration). Docker Compose is the easiest way to run the full stack including FreeSWITCH with pre-configured SIP profiles, dialplan, and XML curl integration.
